# Report — Agent 2: market memory and competitor recall

Branch `agent/2-market-memory`, merged into `main`. Fixes P4, P5 (data side) and D8.

## What changed
- **`recur_deck/market_graph.py`** replaces the stub. Schema as in the brief, plus `summaries` (verifier
  segment/scope per run), `markets` (each target's vertical and segment facts), a `runs` registry and four edge
  types: `competitor`, `verified` (same buyer, not kept), `rejected`, `candidate` (found, never verified).
  Interface: `load`, `for_run`, `from_runs`, `MarketGraph.neighbors(domain, depth=2)`, `.placements(domain)`
  (explicit + derived readings), `.related_targets(entity)`, `.add_run(...)`, `.save()` (atomic, keeps `.bak`).
  Quotes and URLs are stored, not just evidence ids.
  `hooks.after_run` records pass / pass_with_warnings live runs. CLI: `python -m recur_deck.market_graph ingest
  runs/<dir> ...` and `... show <domain>`.
- **`recur_deck/axes.py`** (new, shared with Agent 3): the six ordinal axis kinds with directions, title -> kind
  inference for old decks, and a plain-word cue reader used for derived placements.
- **`stages/competitors.py`**: three new channels.
  - `graph`: `graph_seeds(graph, entity)`.
  - `self_compare`: the target's compare / vs / switch / integration pages.
  - `segment`: up to 2 sub-segments × 2 searches.
  Also: `MAX_VERIFY` 20, weak candidates fill the verification slots, and `segments` / `graph_via` are recorded
  on candidates and competitors. Each kept competitor carries `graph_placements`. `competitors.json` now records
  `searches` per channel, `self_compare_chunks` and `graph_seeds`.
- **Prompts**: `competitor_segments.md` is new. `competitor_extract.md` gained a paragraph on the target's own
  pages; `competitor_verify.md` is unchanged.
- **`tests/fake_world.py`**, additions only: a compare page and Brightpearl (`compare=True`), decorator
  vendors (`segments=True`), a graph-only vendor (`graph_only=True`), and the fake `competitor_segments` answer.

## Credits and cost per run (estimated)
| Addition | Firecrawl searches | Credits | Claude |
|---|---|---|---|
| Sub-segments (0-2, only ones the vertical doesn't name) | +2 each, ≤ +4 | ~6 each, ≤ 12 | 1 Haiku call (< $0.001) |
| Self-compare pages | 0 (map served from cache; direct fetches) | 0 (≤ 4 if a page needs a Firecrawl scrape) | ≤ 1 Haiku extract batch |
| Graph seeds | 0 | 0 | up to 12 seeds, verified only if slots remain |
| Verification cap 14 -> 20, weak fill to 20 | 0 | 0 | up to +8 Sonnet verify calls (≈ $0.01 each) |

At most **+4 searches** (target ≤ 6), about +12 credits worst case. FDM4 would get +2 searches / ~6 credits
("apparel decorators"), and about +$0.10 of Claude.

## Open risks

- Cue reading is plain-word matching. Agent 3 should use derived readings only as history, never as proof.
